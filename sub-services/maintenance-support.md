# **SECTION 02 — DEFINITION**

## **What Is Software Maintenance & Support?**

Software maintenance and support is the ongoing technical work required to keep an existing software application functioning effectively after development and deployment.

Maintenance can involve correcting defects, adapting software to technical changes, improving existing functionality and reducing issues that affect long-term application reliability.

A typical maintenance lifecycle can look like:

**Existing Software**  
 → **Technical Assessment**  
 → **Issues / Improvement Requirements**  
 → **Maintenance Work**  
 → **Testing**  
 → **Release**  
 → **Ongoing Monitoring & Support**

Software maintenance is not limited to fixing bugs. It can also help an application continue operating as technologies, integrations, business processes and user requirements change.

---

# **SECTION 03 — SPECIFIC CAPABILITIES**

## **Our Software Maintenance & Support Services**

### **Corrective Software Maintenance**

Corrective maintenance focuses on identifying and resolving defects within existing software.

This can include:

* Application bugs  
* Failed functionality  
* Unexpected software behaviour  
* Data-processing issues  
* Integration errors  
* Backend problems  
* Frontend defects  
* Workflow failures  
* Regression issues

A typical corrective workflow can follow:

**Reported Issue**  
 → **Investigation**  
 → **Root-Cause Analysis**  
 → **Code Correction**  
 → **Testing**  
 → **Release**

The appropriate correction depends on the underlying cause rather than only the visible symptom.

### **Adaptive Software Maintenance**

Software environments change over time.

Adaptive maintenance helps existing applications continue working when surrounding technologies or requirements change.

This can involve:

* Operating-system changes  
* Browser changes  
* API updates  
* Third-party integration changes  
* Framework updates  
* Database changes  
* Infrastructure changes  
* Security requirements  
* Business-process changes

Adaptive maintenance helps reduce the risk of an application becoming incompatible with the environment in which it operates.

### **Perfective Software Maintenance**

Perfective maintenance focuses on improving existing software rather than correcting a failure.

Potential improvements can include:

* Existing feature enhancements  
* Workflow improvements  
* Usability improvements  
* Performance improvements  
* Code improvements  
* Database optimisation  
* Application responsiveness  
* Technical refinements

The aim is to improve how the existing application performs or supports current business requirements.

### **Preventive Software Maintenance**

Preventive maintenance focuses on reducing the likelihood of future technical problems.

Activities can include:

* Code review  
* Dependency assessment  
* Technical-debt reduction  
* Refactoring  
* Logging improvements  
* Error-handling improvements  
* Test coverage improvements  
* Documentation updates  
* Performance review

Preventive maintenance can make future changes easier and reduce avoidable technical risk.

# **SECTION 04 — HOW IT WORKS**

## **How Software Maintenance Works**

Software maintenance should begin with understanding the existing application before changes are made.

A typical workflow can be:

**Existing Application**  
 → **Codebase & Environment Review**  
 → **Maintenance Requirements**  
 → **Prioritisation**  
 → **Development**  
 → **Testing**  
 → **Deployment**  
 → **Ongoing Review**

### **Existing Software Assessment**

Before ongoing maintenance begins, available technical information can be reviewed.

This may include:

* Application architecture  
* Source code  
* Frameworks and libraries  
* Database structure  
* APIs  
* Third-party integrations  
* Deployment environment  
* Existing documentation  
* Known issues  
* Current development workflow

The level of assessment required depends on the application's size, condition and available documentation.

### **Issue Prioritisation**

Not every maintenance requirement has the same urgency or business impact.

Issues can be organised according to factors such as:

* Severity  
* User impact  
* Business impact  
* Technical risk  
* Dependency on other work  
* Implementation complexity

This helps distinguish urgent defects from routine improvements and longer-term maintenance work.

### **Development & Testing**

Approved maintenance changes are implemented and tested before being introduced into the production environment.

Testing requirements can depend on:

* Type of change  
* Application architecture  
* Existing automated tests  
* Connected functionality  
* Integration dependencies  
* Deployment process

## **Software Maintenance vs Technical Support**

Software maintenance and technical support are related services, but they address different parts of the support lifecycle.

| Software Maintenance & Support | Technical Support |
| ----- | ----- |
| Maintains the application itself | Helps diagnose technical issues |
| Changes and fixes software code | Troubleshoots reported problems |
| Updates existing functionality | Investigates incidents |
| Handles compatibility changes | Supports issue resolution |
| Improves application maintainability | Provides technical assistance |
| Ongoing engineering work | Problem-focused support |

A typical relationship can be:

**Issue Reported**  
 → **Technical Support Investigation**  
 → **Code-Level Problem Identified**  
 → **Software Maintenance**  
 → **Fix Tested & Released**

# **SECTION 14 — FAQ**

## **Frequently Asked Questions About Software Maintenance & Support**

### **What are software maintenance and support services?**

Software maintenance and support services involve maintaining existing applications through bug fixing, software updates, compatibility work, technical improvements and ongoing engineering support.

### **What are the main types of software maintenance?**

Common categories include corrective maintenance for defects, adaptive maintenance for environmental changes, perfective maintenance for improvements and preventive maintenance intended to reduce future technical problems.

### **What is corrective software maintenance?**

Corrective maintenance focuses on identifying and fixing defects or unexpected behaviour in existing software.

### **What is adaptive software maintenance?**

Adaptive maintenance updates software so it can continue operating when technologies, integrations, platforms or business requirements change.

### **What is preventive software maintenance?**

Preventive maintenance focuses on improving maintainability and reducing future technical risk through activities such as refactoring, dependency assessment and technical-debt reduction.

### **Can you maintain software developed by another company?**

Existing software can potentially be taken over for maintenance after the application, source code, technical environment and available documentation have been assessed.

### **Can software maintenance include new features?**

Maintenance can include improvements and extensions to existing functionality. Larger new functionality may instead require a separate software-development scope.

### **What is the difference between software maintenance and technical support?**

Software maintenance involves making changes to the software itself, while technical support focuses more directly on diagnosing and resolving reported technical problems.

### **Can you maintain legacy software?**

Legacy applications can potentially be maintained while a business continues using them or plans a broader modernisation strategy. Feasibility depends on the technology, source code and technical environment.

### **Does software maintenance include bug fixing?**

Yes. Bug fixing is a common part of corrective software maintenance.

### **Does software maintenance include performance optimisation?**

Performance improvements can form part of maintenance where existing application behaviour or technical bottlenecks require investigation and optimisation.

### **How much does software maintenance cost?**

Cost depends on the software's complexity, condition, required maintenance work, integrations, testing requirements and level of ongoing engineering support.

### **How long does software maintenance last?**

Maintenance can continue for as long as an application remains operational and requires technical updates, fixes, improvements or compatibility work.
