# **Public, Private & Permissioned Blockchain**

Different blockchain models support different requirements.

## **Public Blockchain**

Public blockchain environments typically allow wider participation according to network rules.

They may be relevant where open verification, decentralised participation or public blockchain interaction forms part of the application.

## **Private Blockchain**

A private blockchain operates within a controlled environment where participation is restricted.

This can be relevant where organisations require greater control over access and governance.

## **Permissioned Blockchain**

Permissioned architectures can give different participants defined levels of access.

Users may have different permissions to:

* Read  
* Write  
* Validate  
* Approve  
* Administer

The appropriate model depends on privacy, governance, users, transaction requirements and integration needs.

# **Frequently Asked Questions**

### **What are blockchain and Web3 development services?**

Blockchain and Web3 development services include planning, architecture, application development, smart contracts, DApps, wallet integrations, blockchain integrations, testing and deployment of decentralised or blockchain-enabled digital products.

### **What is the difference between blockchain and Web3?**

Blockchain is the underlying distributed-ledger technology used to record and verify transactions or data. Web3 is a broader application ecosystem that can use blockchain, smart contracts, wallets and decentralised technologies to create user-facing digital products.

### **What does a blockchain and Web3 development company do?**

A blockchain and Web3 development company helps define use cases, design technical architecture and develop blockchain-enabled applications, smart contracts, DApps, wallet functionality and integrations.

### **What can you build with blockchain and Web3?**

Blockchain and Web3 technologies can be used for decentralised applications, smart-contract systems, digital asset platforms, wallet-enabled applications, blockchain integrations, enterprise systems and NFT marketplaces where appropriate.

### **Do all applications need blockchain?**

No. Many software products are better suited to conventional application architecture. Blockchain should be used where decentralisation, distributed trust, digital ownership or programmable transactions provide genuine value.

### **What is a DApp?**

A DApp is a decentralised application that interacts with blockchain infrastructure, often through smart contracts and wallet connections.

### **What is a smart contract?**

A smart contract is programmable logic deployed to a blockchain network that can execute defined actions or conditions.

### **Can blockchain integrate with existing software?**

Yes. Blockchain functionality can be connected to existing applications, APIs, backend systems, databases and other business software where the technical architecture supports it.

### **Can you develop crypto wallets?**

Wallet functionality can be designed and developed for blockchain applications where wallet connectivity, asset interaction or transaction functionality forms part of the project.

### **Can you develop NFT marketplaces?**

NFT marketplaces can include wallet connectivity, digital asset listings, smart contracts, user profiles, marketplace functionality and blockchain integration.

### **How secure are blockchain applications?**

Blockchain technology has built-in technical characteristics, but applications, smart contracts, wallets, APIs and integrations can still contain vulnerabilities. Security therefore needs to be considered throughout architecture, development, testing and deployment.

### **How much does blockchain and Web3 development cost?**

Cost depends on product scope, architecture, blockchain network, smart contracts, application functionality, wallet requirements, integrations, UX/UI, security, testing, infrastructure and maintenance.

### **How long does blockchain and Web3 development take?**

The timeline depends on application complexity, architecture, smart contracts, integrations, number of features, testing, security requirements and stakeholder feedback.
